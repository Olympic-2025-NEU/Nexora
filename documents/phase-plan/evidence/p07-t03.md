# P07-T03 — Step 0 contract findings (2026-11-23)

- Inventory (`contexts/inventory/application/adjust-stock.ts`): `findBalancesOrdered` is a sorted Prisma `findMany`, **not** `FOR UPDATE`. Missing receipt balance is inserted as zero via `createMany(skipDuplicates)` before increment; missing issue balance throws `DomainError("INSUFFICIENT_STOCK", 409)` without requested/available details. `openStockBalance` delegates to `adjustStock`. T03 must lock sorted balance rows and translate insufficient stock to 422 with details; receipt uses existing port.
- Pipeline (`platform/http/pipeline.ts`, `platform/http/idempotency.ts`): lookup happens after authorization, before domain/version guard. Completed response JSON is persisted and returned on replay. Claim, domain, outbox, and completion share transaction; failed commands roll back claim and can retry with same key. Same scoped key with different payload throws 409 `IDEMPOTENCY_CONFLICT` while unexpired.
- Bridge (`platform/workflow/approval-service.ts`, `tests/platform/workflow-bridge.integration.test.ts`): submit uses `createRequest(tx, {documentId, submittedDocumentVersion, creatorSub, warehouseIds, lineSnapshotSha256})`; unique `documentId` allows only one request. Decisions require `recordDecisionIntent` with different active approver, matching scope, task ID and version; `createFlowableDecider` drives engine and `reconcileApproval` syncs state. `confirmApproval` checks current scope and snapshot and transitions approval in caller transaction; `cancelRequest` does not accept approved requests.
- Catalog (`contexts/catalog/infrastructure/prisma-repos.ts`, `prisma/schema.prisma`): `catalog.product_variant_uom.factor_to_stock_uom` is authoritative, stock row has factor 1; packing is not conversion source. Batch stores `expiresOn` and `qualityStatus` (`available`, `restricted`, `inspect`); new batch defaults to `inspect`.

## Contract deviations requiring explicit treatment

- `platform/persistence/transaction.ts` defaults to Serializable; R3 forbids that for trading confirm. Use a trading-specific caller-owned ReadCommitted unit of work with ordered row locks; leave platform pipeline unchanged.
- Bridge `cancelRequest` only transitions requested/starting/pending/decision_pending, while R1 requires cancellation after approval. Do not patch bridge internals or write approval state directly. Until owning bridge exposes an approved-state cancellation operation, approved issue cancellation must return typed conflict. Keep this T03 criterion unticked.
- Bridge approval state changes do not update `trading.document.status`. Confirm must consume bridge-approved state without assuming document is already `approved`; document remains `pending_approval` until confirm. Record this divergence in final evidence.
- Bridge snapshot contract takes `quantity: number` (JSON hash); stock quantity and movement remain Decimal. Convert only at hash boundary after Decimal validation; do not use JS number for stock arithmetic.
