# P08-T05 — Passport publication policy evidence

Date: 2026-11-24. Task branch: `phase08/p08-t05-passport-policy`.

## Implementation

- Migration `20261124010000_passport_policy` adds per-batch policy versions with five `private|partner|public` categories, private defaults, constrained draft/approved/revoked lifecycle, actor and timestamps. One draft and one approved version at most can exist per batch. Old versions remain for audit. Only an authenticated organization Administrator can draft, approve, revoke or rebuild through `/api/v1/lots/{id}/passport-policy` and its action routes.
- Approval builds `passport_projection` in the same transaction and records an audit entry. The builder copies exactly `productName`, `publicLotCode`, `originIssuer`, `timeline`, `verificationState`, `gaps`, `asOf` from available batch/product and confirmed local trace events. It never serializes raw event summaries, buyer references, member data, prices, stock or attachment rows. `partner_asserted` sources become an explicit unverified gap. Evidence remains omitted until T07 links clean, public-authorized attachments; setting evidence visibility alone does not disclose a file.
- An active projection requires an approved policy, `available` batch and public organization/product/batch fields. Timeline is empty unless public. A trace outbox insert or trace event insert makes an active projection stale; a quality status change revokes it. Rebuild while a source outbox is pending remains stale with `projection_pending`; restricted batches remain revoked. Rebuild and owner revoke are audited. Policy rows are retained, never overwritten; API responses use `private, no-store`. T06's public endpoint must check `state=active` on every request and use `no-store` so revoked/stale projections cannot be served from cache.
