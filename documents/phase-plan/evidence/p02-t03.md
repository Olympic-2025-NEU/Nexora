## Security Properties

1. **Methods:** GET and HEAD only at gateway. App also returns 405 for POST/PUT/PATCH/DELETE.
2. **Token format validation:** `^[a-zA-Z0-9_-]{10,128}$` — rejects path traversal, SQL injection, XSS.
3. **404 for unknown tokens:** Never reveals batch IDs or internal IDs for unrecognised tokens.
4. **No authentication required** for the route itself.
5. **Rate limited:** 30 req/s with burst of 15 (gateway limit-req plugin).
6. **Cache-control: no-store** on all responses to prevent proxy caching.
7. **Response projection:** safe fields only — no `batchId`, `lotId`, internal UUIDs, or PII.

---

## Stub Status

The handler returns `404` for all tokens at this stage. Full implementation deferred to P08/P09 when the passport/batch registry is built. This is the safe default (better to 404 now than leak batch IDs with a stub 200).
