## Permission change between draft and confirm

Semantics (chairman ruling): authorization is evaluated at action time against the actor's
CURRENT scope. Test: draft created with warehouse scope, scope revoked (unitIds = []),
confirm rejected with 403 WAREHOUSE_SCOPE_REQUIRED for receipt, issue and stocktake;
confirm with scope intact succeeds. (Sale revocation was already covered by the T06 battery.)

## Global invariant scan

Runs as the final conformance test over every document in the battery database (both test
files' fixtures): every stock balance equals the sum of its movement deltas; no
non-confirmed document has movements; every confirmed document matches the effect matrix
(movement counts, confirm audit present, outbox counts). PASS.

## Document history API + UI

- `GET /api/v1/documents` — filters: type, status, batchId (via lines), partnerId (matches
  transfer destination partner OR receiving source partner resolved via issuer instance id),
  from/to (createdAt, `to` exclusive), cursor pagination in the codebase convention
  (limit + nextCursor). Deviation from the T08 plan, recorded: the plan asked for
  limit/offset + total count; the implementation follows the established per-type list
  convention (cursor), which also removes the scoped-count leak surface entirely.
- `GET /api/v1/documents/{id}` — document + lines + stock movement references + approval
  reference (state, Flowable process instance) + delivery state + linked documents
  (linked issue, corrections). Live joins only, no projection table; P08 traceability
  remains the owner of cross-instance lineage.
- Authorization: new policy `trading:history:read` (staff/approver/viewer, admin always);
  list results and counts are scoped by the actor's warehouses exactly like the per-type
  lists; detail returns 403 when any line is outside the actor's scope.
- UI: `/trading/history` (filterable list) + `/trading/history/[id]` (detail,
  `export const instant = false`).
