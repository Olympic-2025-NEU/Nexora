### OIDC Plugin Configuration

```yaml
openid-connect:
  discovery: "${OIDC_ISSUER_URL}/.well-known/openid-configuration"
  # Keycloak internal URL: http://keycloak:8080/realms/nexora/.well-known/openid-configuration
  client_id: "${OIDC_GATEWAY_CLIENT_ID}"
  client_secret: "${OIDC_GATEWAY_CLIENT_SECRET}"
  bearer_only: true
  realm: nexora
  set_access_token_header: false
  set_userinfo_header: true
```

**Note on env substitution:** APISIX standalone YAML config does not natively substitute `${VAR}` from the host environment. Options:
1. Use a `envsubst`/`sed` preprocessing step in Compose entrypoint.
2. Replace `${OIDC_ISSUER_URL}` with the literal internal URL `http://keycloak:8080/realms/nexora` — documented in comments in `routes.yaml`.
3. Use APISIX admin API (not standalone mode) to push routes with values.

The literal fallback for Demo Compose is: `http://keycloak:8080/realms/nexora/.well-known/openid-configuration`.

## Identity Header Stripping

The `serverless-pre-function` plugin at `phase: access` removes the following headers before OIDC processing:

```
x-userinfo, x-access-token, x-authenticated-user,
x-remote-user, x-forwarded-user, x-consumer-username,
x-consumer-id, x-consumer-custom-id
```

App layer (`platform/identity/request-auth.ts`) also detects and rejects these headers when the app is called directly (defence-in-depth).
