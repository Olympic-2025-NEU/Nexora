# P08-T03 — Backward trace evidence

Date: 2026-11-24. Task branch: `phase08/p08-t03-backward-trace`.

## Implementation

- `contexts/traceability/application/backward.ts` traverses only stored directed `trace_link` sources. Root events are confirmed provenance for a local batch, optionally narrowed by document. BFS marks visited event IDs, limits source-link hops to 10, freezes a recorded-at snapshot in the cursor and caps a query at 2000 nodes. Each response page includes source document/event/version, issuer-qualified origin lot, verification state, occurred/recorded times, edges, gaps and local projector state.
- `contexts/traceability/infrastructure/backward-repo.ts` reads from app trace tables with the snapshot cutoff. The protected route `/api/v1/lots/{id}/trace/backward` checks the authenticated membership and `trace:read` policy, validates parameters and disables caching. The `/trace` UI permits batch/document lookup and shows timeline context, explicit links, missing sources and lag.
- Local transfer/sale events point to their confirmed issue sources. Receiving points to an issuer-qualified remote `missingRef` until P09 verifies and resolves the partner source. Receipt and issue events sharing a batch are shown as context only: M03 does not record receipt-to-issue allocation, so the query reports `local_allocation_unknown` rather than a false causal edge. The open T01 allocation checkbox remains open.

## Boundary

The graph cannot claim a complete A→B→C chain in P08. Remote confirmation and reconciliation belong to P09; local receipt-to-issue quantity allocation requires an explicit M03 source mapping before a causal edge can be asserted. The 2000-node query cap is reported as `truncated` with a `node_limit` gap; callers can narrow by `documentId`.
