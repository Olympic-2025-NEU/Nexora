# P08-T02 — local trace projector

Date: 2026-11-23. Task branch: `phase08/p08-t02-trace-projector`.

## Implemented

- Confirmed M03 transfer now emits `trading.transfer.confirmed.v1` to traceability in the same command transaction as its federation announcement. Receiving emits `trading.receiving.confirmed.v1` with all sent/actual lines, including zero actual quantity. The six supported trading event types reach the same versioned router.
- The outbox consumer validates the v1 payload, the confirmed source document/version, line identities and quantities against PostgreSQL. One source event spanning multiple batches produces a stable issuer-qualified event ID per batch. A duplicate replay with changed source/checksum is rejected. Transfer/sale links wait for the local confirmed issue event; receiving links to a precise issuer-qualified remote event gap from the stored inbound message, never an invented upstream node.
- The worker uses the existing lease, retry and dead-letter dispatcher. Trace inserts/link writes happen through `app_runtime` and the private `core_record(kind='trace_projection',source_type='lot')` writer uses a separate internal `core_data` connection. If the second write fails, outbox retry reuses the immutable trace event and rebuilds the core projection. Projection payload follows the JSON Schema, sorts events/edges deterministically and uses JCS SHA-256 and version CAS. The browser cannot write this record.
- `/api/v1/trace/status`, `/trace` and worker metrics report local pending count and oldest lag. The worker logs `trace.projector.lag` above 300 seconds. The UI labels an empty local queue without asserting that remote partner history is complete.

T03 backward query must show the same-batch timeline as provenance context and mark unresolved upstream gaps. P09 resolves cross-instance gaps after validated inbox processing.
