# P04-T03 — Transactional outbox and worker

**Date:** 2026-11-20. **Branch:** `phase04/p04-t03-outbox-worker`.

## Implementation and decisions

- Hand-authored Prisma migration `20261120010000_platform_delivery_outbox` adds the blueprint `platform.outbox_message`, unique tuple, status/attempt CHECKs, partial due index and correlation index. `app_runtime` has SELECT/INSERT/UPDATE, not DELETE; `core_data` has no grant. No `delivery_attempt` table (P09).
- `ctx.emit(event)` registers zero-to-many events in the domain callback. The pipeline calls `appendOutbox(tx, events)` after domain work and before idempotency completion in the same Prisma unit of work. A unique collision aborts the command; rollback leaves no outbox row. A replay skips the domain and writer. Transaction callback retries clear prior, rolled-back emissions.
- T03 supersedes T01's post-commit `DispatchPort` and `UnimplementedDispatch` step behavior, and T02's dispatch-double assertion. The `commit` step remains in the ordered registry, without a losable wake-up signal. T01/T02 evidence files are historical and unchanged; T02's deferred *literal outbox row* assertion now runs in this task's suite.
- Dispatcher claims due and expired-lease rows using PostgreSQL `now()` and `FOR UPDATE SKIP LOCKED`, gates later versions for the same aggregate/destination, and uses fenced completion (`id`, leased status, worker owner, attempt count). A crashed lease at the eighth attempt dead-letters without a ninth delivery. Failures use capped exponential full jitter. Unknown destinations retry with `UNKNOWN_DESTINATION` from attempt one. A dead-letter predecessor **does not block** successors; P04-T04 handlers must tolerate version gaps and inspect dead-letter metrics. `retryDeadLetter` is internal; permissioned admin API and audit remain P04-T07.
- Existing `worker` process polls once per second and runs a separate hourly idempotency purge timer, both using the shared Prisma client. Purge scheduling was deferred by T02; this always-on process owns the timer so a dispatcher tick cannot couple the two jobs. `/metrics` reports real pending + retry_due + leased queue depth and dead-letter count. A TypeScript `build:worker` step emits CommonJS under `worker/dist` for the existing plain-JS worker image; no production `tsx`.
- Production handler map is **empty** until T04 local handlers and P09 federation transport. All receiver-delivery evidence below is **simulated delivery against the handler port**, not real HTTP, partner ACK, or production consumption. The child-process SIGKILL test uses the same dispatcher with a test-only recording receiver, deduping message IDs across restarts. Redis never replaces PostgreSQL outbox state.
- No delivered-row retention policy exists in the blueprint; decide retention at T07/P12. Dead-letter rows are not purged. Defaults: lease 30 s, batch 10, max attempts 8, full-jitter backoff 2 s to 300 s, poll 1 s, idempotency purge hourly.
