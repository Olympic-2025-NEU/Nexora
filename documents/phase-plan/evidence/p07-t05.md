## Implementation and deviations

- `platform.inbound_message` is a dedicated seeded fixture store, not the sender outbox. The internal-only seed service writes JCS SHA-256; resolve rehashes stored JSON and checks the v1 schema, recipient, event type, unique source lines and sent total. Store mutation after seeding fails verification; mutation of the sender outbox does not change the seeded copy. No public seed endpoint exists. Fixture verification does not prove partner identity or cryptographic signature.
- Deferred active-source constraint triggers on receiving detail and document permit cancelled draft replacement and block two non-cancelled receipts. The source advisory lock in application is backed by the deferred trigger at commit. PostgreSQL `pg_advisory_xact_lock` returns `void`; Prisma raw query requires a `::text` cast for that return value.
- **DB-order deviation from R5:** T02 `guard_detail` prohibits updating receiving detail once the document is confirmed, even in the same transaction. Confirm validates and writes detail totals *before* the versioned `draft → confirmed` transition, then posts movement and two outbox messages atomically. Rollback reverts all changes.
- Internal event uses `trading.receipt.confirmed.v1` with only movement-producing lines. Its schema previously required at least one line. Allowing `lines=[]` is necessary for valid all-zero receiving without creating a fictitious stock movement. Federation reply includes every actual line, including zeros, and only positive local lots.
- Catalog batch creation remains in catalog. Existing unique `(originIssuerInstanceId, originLotId)` limits one local batch per upstream lot. UI shows seeded provenance and makes actual inputs empty initially.
