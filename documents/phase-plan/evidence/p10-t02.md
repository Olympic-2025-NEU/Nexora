# P10-T02 — Tool registry, actor scope, quota and audit

Date: 2026-11-26. Branch: `phase-10`. Depends on [D09](../../adr/0009-ai-provider.md) and [T01](p10-t01.md). AC-10/11 remain open until P10-T03/T04/G10.

## Contract and execution boundary

- Exactly five input schemas with `additionalProperties:false`: `getLot`, `getStock`, `getTrace`, `createReceiptDraft`, `createIssueDraft` in `services/ai/tools/`. Destructive actions, arbitrary SQL and arbitrary URLs are absent. Quantity, depth, UUID, note and purpose are bounded.
- `composition/ai.ts` resolves a user Bearer against Keycloak and current membership; the internal executor calls existing M02/M03/M04 HTTP APIs over fixed ERP loopback using that same user token. Each business route verifies the actor/policy again. Python inference gets no user/Admin token and no DB credential. There is no public tool route at T02.
- Warehouse-specific requests reject nonmember Staff with 403 before a business call; business API may independently return 403. `getStock` reports only the visible 20 balances and marks truncation. `getTrace` projects source event IDs, verification state and gaps without raw summary/private payload. Both draft tools resolve batch/variant/UOM, require stable idempotency key, check issue stock at request time and POST only `/receipts` or `/issues`; confirm remains a separate M03 action.
- Per-actor PG audit reservations cap 30 tool calls/minute and 5 draft calls/minute with an advisory transaction lock. Completion records `ai.tool.<name>` outcome and allowlisted UUID source IDs in `platform.audit_log`. Token/prompt/raw response do not enter audit. A failed request retains its short-lived quota reservation; this bounds repeated failures.
