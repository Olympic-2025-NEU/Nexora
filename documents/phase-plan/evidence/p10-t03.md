# P10-T03 — Tra cứu lô có dẫn nguồn

Date: 2026-11-26. Branch: `phase10/p10-t03-lot-lookup`. Depends on T01/T02. AC-10 evidence only; AC-11 remains open for T04/G10.

## What was built

- Deterministic orchestration in `contexts/ai/application/chat-lot-lookup.ts`: pattern-based lot/issuer resolver, actor-visible candidate list, `getLot`/`getStock`/`getTrace` calls through the T02 registry, fact bundle, Vietnamese template answer, post-generation verifier, and `ai.chat.answer` audit entry.
- Adapter client `contexts/ai/infrastructure/ai-generate-client.ts`: loopback/internal-host only, `AI_PROVIDER` gate, 30s timeout, 10-fact body `{question, facts}`, internal-token header, silent `null` on 503/timeout. No user Bearer and no prompt logging.
- Routes `app/api/v1/ai/chat/route.ts` plus `/ai/chat` alias, wired through `composition/ai.ts`; no public tool route. Every call resolves the user Bearer and current actor.
- Page `/assistant` with candidate picker, sourced answer card, structured chips, `AI_UNAVAILABLE` fallback and link to `/trace`; `instant = false`. Navigation and en/vi strings added.
- Audit extension in `platform/audit/prisma-audit-recorder.ts`: allowlisted rendered `quantity`, `unit`, `asOf`, `verification` in `ai.chat.answer` summaries; question and model text excluded.
- Demo fixture in `deploy/scripts/seed-abc.mjs`: `LOT-A-001` from two issuers on instance A, recorded in `fixture-manifest.json`. `services/ai/README.md` documents shell-level provider override without editing ignored instance env files.
- Unit tests `contexts/ai/application/chat-lot-lookup.test.ts` (7 tests) and Vietnamese golden tests `tests/ai/lot-lookup.golden.test.ts` (6 tests), wired to `npm test` via `test:ai:golden`.

## Chairman rulings

| Ruling | How satisfied |
| --- | --- |
| R1 — model never writes numbers | `renderAnswer` renders every number, unit, source ID, timestamp and verification from the fact bundle. Model output is only a short connector appended after `verifyModelText` passes; rejected output leaves pure template answer. |
| R2 — no model tool choice or authority parsing | `extractLotCodes`/`extractIssuers` and `resolveLot` use fixed patterns and T02 tools only. Model receives no tool schema and no authority decision. |
| R3 — backend disambiguation | `ambiguous` returns candidates and stops before `getStock`/`getTrace`/generation; no conversation store. Client re-POSTs chosen `batchId`. Candidates come from actor-scoped `getLot` calls plus actor-org/`allowedIssuers` visibility filter; unauthorized lots never enter the list. `not_found` stops with a `/trace` hint. |
| R4 — deterministic fact policy | `buildFactBundle` takes ≤10 facts in fixed order: lot identity, current total + unit, ≤3 warehouses, ≤3 newest events, verification/gaps. `renderAnswer` states hidden warehouse/event counts explicitly when truncated. |
| R5 — audit closes AC-10 gap | `ai.chat.answer` stores rendered `quantity`, `unit`, `sourceIds`, `asOf`, `verification`, `requestId` and tool-call count via `prismaAuditRecorder`; sanitizer allowlists those fields. No prompt or model text. Golden AC-10 test compares answer ↔ audit ↔ tool result for the same request. |
| R5b — post-verifier | `verifyModelText` rejects any number, UUID, unit, credential/instruction pattern not present in the fact bundle; rejected connector is dropped. |
| R6 — partner data as data | `sanitizePartnerText` strips control characters, truncates values, and redacts instruction/PII/credential patterns before facts, template rendering and model input. Unit test asserts redaction. |
| R7 — Vietnamese golden fixtures | Golden tests use seeded A/B/C-style values, duplicate `LOT-A-001` across `nexora-a`/`nexora-b`, `dev-staff` actor, and cover exact numbers, missing lot, duplicate code, provider 503, warehouse 403 and AC-10. Adapter is mocked at its `{question, facts}` contract; no live model in CI. |
| R8 — panel deferred | Only `/assistant` ships in T03. Lot/document page panel deferred to T03b or merged into T06; recorded in `phase-10-ai.md` and `ui-ai-spec-v1.md` in this change. |
| R9 — demo backbone first | Seed duplicate-lot fixture and provider/fallback documentation are in place. Live `qwen3:0.6b` pull, instance-A profile startup and pre-warm were not run as part of these code steps; no instance env file was read. Mocked 503 proves template fallback; Milo must run the live dev smoke before demo. |
| R10 — bounded presentation | Chips render value, unit, source ID (linked to `/trace`), `asOf` and verification from structured facts, never from model text. Answer card shows "Đã đối chiếu với N lượt gọi tool." No new drill-down. |
