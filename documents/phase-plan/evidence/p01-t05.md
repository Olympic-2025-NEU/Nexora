## Config matrix

Each row applies independently to A, B and C; no credentials are shared across instances. `deploy/config.mjs --file` validates the complete env contract before Compose. The process-level checks validate only values injected into that process by Compose. Values labeled *metadata* are validated at bootstrap but have no runtime consumer in P01.

`erp` receives `DATABASE_URL` from `APP_DATABASE_URL`, `OIDC_ISSUER_URL`, `PUBLIC_BASE_URL`. `worker` receives `DATABASE_URL` from `APP_DATABASE_URL`, `FLOWABLE_BASE_URL`, `REDIS_URL`. `core-data` receives `CORE_DATABASE_URL`, `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET_PRIVATE`. These three processes validate their injected fields before serving. Bucket names include instance ID; project names, ports, Docker network/volume names, admin DB names and generated credentials remain independent.

## Fresh checkout preparation and Compose validation

Node 22.23.1 and Docker 29.8.2. Host has no Docker Compose plugin. Used `docker:29-cli` Compose v5.7.1 with the host socket and same-path checkout mount (`--security-opt label=disable` for this SELinux host); `config -q` never emits interpolated credentials. Test-only env files were generated under ignored `deploy/instances/*.env`, all mode `0600`.

```sh
node deploy/scripts/prepare.mjs a
node deploy/scripts/prepare.mjs b
node deploy/scripts/prepare.mjs c
node deploy/config.mjs --file deploy/instances/a.env
node deploy/config.mjs --file deploy/instances/b.env
node deploy/config.mjs --file deploy/instances/c.env
# Then removed only the locally generated b.env and reran the full shell bootstrap:
# docker() wraps: docker run --rm --security-opt label=disable -e DOCKER_HOST=unix:///var/run/docker.sock \
#   -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD:$PWD" -w "$PWD" docker:29-cli docker "$@"
docker() { command docker run --rm --security-opt label=disable -e DOCKER_HOST=unix:///var/run/docker.sock -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD:$PWD" -w "$PWD" docker:29-cli docker "$@"; }
export -f docker
bash deploy/scripts/bootstrap.sh b
bash deploy/scripts/bootstrap.sh a
bash deploy/scripts/bootstrap.sh c
```

Results: `Created` for all three env files; three `Config valid` responses; shell bootstrap for newly removed B printed `Created deploy/instances/b.env`, `Config valid`, `Ready: ... up -d --build`. Repeated A/C runs printed `Using existing ...`, validated and finished `compose config -q` with exit 0. Separate check below revalidated all three using the actual generated env files after PowerShell recreated C:

```sh
docker run --rm --security-opt label=disable -e DOCKER_HOST=unix:///var/run/docker.sock \
  -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD:$PWD" -w "$PWD" docker:29-cli \
  sh -c 'for i in a b c; do docker compose -f deploy/compose.yml --env-file deploy/instances/$i.env -p nexora-$i config -q || exit; done'
stat -c '%a %n' deploy/instances/a.env deploy/instances/b.env deploy/instances/c.env
```

## Failure checks and application startup

```sh
npm test
set -o pipefail
for key in INSTANCE_ID APP_DATABASE_URL OIDC_ISSUER_URL PARTNER_OUTBOUND_TOKEN_URL S3_BUCKET_PRIVATE FLOWABLE_BASE_URL REDIS_URL AI_BASE_URL; do
  for mode in missing invalid; do
    output=$(KEY="$key" MODE="$mode" node -e 'const text=require("node:fs").readFileSync("deploy/instances/a.env","utf8");process.stdout.write(text.split("\n").map(line=>line.startsWith(process.env.KEY+"=")?(process.env.MODE==="missing"?"":process.env.KEY+"=sensitive_should_never_print"):line).join("\n"))' | node deploy/config.mjs --file /dev/stdin 2>&1) && exit 1
    if [ "$output" != "Invalid or missing $key" ]; then exit 1; fi
  done
done
docker run --rm nexora-erp:p01-t05
docker run --rm nexora-erp:p01-t05 node worker/entrypoint.js
docker run --rm nexora-core-data:p01-t05
```

Results: `npm test` passes 12 config checks (including A/B/C uniqueness, missing/invalid per group, optional AI reference, CLI rejection and process-level validation) plus 59 OpenAPI paths and SPDX. CLI negative check passed **16/16**: each error named only the removed/malformed variable, with no injected sentinel value. First attempted CLI harness with `spawnSync(..., input)` and `/dev/stdin` failed with `Invalid or missing config file` because Node could not open that stdin descriptor in the synchronous child. Repeated using a shell pipe; all 16 checks passed. The ERP image exits before `next start` with `Invalid or missing DATABASE_URL`; worker exits before its loop with `Invalid or missing DATABASE_URL`; core-data exits before listening with `Invalid or missing CORE_DATABASE_URL`. No secret values appeared in output. Docker image builds for ERP and core-data, `npm run lint`, `npm run build`, `npm run typecheck` passed. Full `up`/service readiness not exercised: existing `nexora-t04` gateway occupies A's loopback port; P01-T05 minimum boot-path check is parser + Compose config on A/B/C, not P01-T06 readiness or P01-T07 reinstall gate.
