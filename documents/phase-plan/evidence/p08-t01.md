# P08-T01 — provenance schema and source guard

Date: 2026-11-23. Task branch: `phase08/p08-t01-provenance-links`.

## Implementation

- `20261123060000_traceability_baseline` adds `trace_event`, `trace_link`, `passport_projection` and `qr_token` in the `traceability` schema. Event identity is `(issuer_instance_id, external_event_id)`; a partial unique index also prevents duplicate `(document_id, batch_id, event_type)` local source actions. Batch and document foreign keys preserve the source; `evidence_refs` holds attachment IDs for T07 review. Event type, origin tuple, local batch line and confirmed document status are checked by a database trigger. Confirmed provenance is append only.
- `TraceWritePort` and its Prisma transaction repository append local events/links and locate the event for a confirmed source. Local event summary and evidence references use JCS before SHA-256. Link targets are either an existing event or an issuer-qualified missing reference, with distinct verification states.
- Passport projections start `stale`; QR tokens start `revoked`. Neither is published by T01. The application role can insert provenance but cannot update/delete trace events or links; the `core_data` role has no trace event read grant.
