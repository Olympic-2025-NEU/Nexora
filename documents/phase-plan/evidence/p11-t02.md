# P11-T02 — DX-Lab shell, session and role boundary

Date: 2026-11-27. Branch: `phase-11`. G11 remains open; this is task evidence, not phase sign-off.

## Implemented

- DX-Lab runs as its own Next.js 16 process behind APISIX `/dxlab`. The server performs OIDC authorization code with PKCE, state and nonce checks, and keeps access/refresh tokens in encrypted, HttpOnly, SameSite cookies scoped to `/dxlab`. Login callback verifies the ID token and resolves the actor through the gateway `/api/v1/me` before creating a session. Logout clears local cookies and calls Keycloak's RP-initiated logout endpoint.
- Workspace navigation reads the organization and roles from the authenticated server response. `/members` checks the administrator role on the server, independently of link visibility. Protected pages redirect to sign-in or refresh; `/api/session` reports 401/403 without token details. Deep links are constrained to `/dxlab` and retained after login.
- A typed DX-Lab client is generated from OpenAPI. The `/api/v1/me` contract now describes the actual raw actor projection returned by the ERP route; the contract validator explicitly checks that exception. DX-Lab has no DB, S3, Flowable or Keycloak Admin credential.
- The shell includes semantic navigation, a skip link, visible keyboard focus, responsive layout and light/dark colors. The role-to-navigation mapping has tests for Administrator, Staff, Approver, Viewer and empty roles. Further H/P/D/I journeys belong to T03–T07.
