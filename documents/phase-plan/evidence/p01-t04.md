# P01-T04 — Keycloak, gateway, Flowable, and storage bootstrap evidence

**Date:** 2026-11-17

**Branch:** `phase01/task04`

**Test instance:** `INSTANCE_ID=t04`, project `nexora-t04`, fresh `nexora-t04-pg` and `nexora-t04-seaweed` volumes. Only example `CHANGE_ME_*` credentials used during local smoke checks; none committed as runtime credentials.

Host Docker 29.8.2 lacks the Compose plugin. Compose v5.7.1 ran in pinned-by-version `docker:29-cli`, with host socket and same-path checkout bind-mounted. This SELinux host needs `--security-opt label=disable` on that **CLI helper**. Service bind mounts use `:z` labels. The Compose entrypoint remains `deploy/compose.yml`.

```sh
docker run --rm --security-opt label=disable -e INSTANCE_ID=t04 -e DOCKER_HOST=unix:///var/run/docker.sock \
  -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD:$PWD" -w "$PWD" docker:29-cli \
  docker compose -f deploy/compose.yml --env-file deploy/instances/a.env.example \
  -p nexora-t04 up -d keycloak-bootstrap gateway seaweedfs flowable
```

Initial run failed: `storage-bootstrap` could not read its bind-mounted script (`MODULE_NOT_FOUND`) on SELinux. Adding `:ro,z` to service bind mounts fixed this. SeaweedFS next failed to read a `0600`/`0640` config file from the shared volume. Its own process needed `0644` on that file; the file is only in the instance-specific Docker volume mounted by storage bootstrap and SeaweedFS. No config or secret was written to the checkout. Re-running the command succeeded: PostgreSQL healthy, `db-bootstrap` exit 0, `keycloak` healthy, `keycloak-bootstrap` exit 0, gateway started, `storage-bootstrap` exit 0, SeaweedFS healthy, Flowable healthy. Keycloak bootstrap printed `Keycloak realm nexora: clients and optional dev user ready`; storage bootstrap printed `SeaweedFS: per-consumer S3 config ready`.
