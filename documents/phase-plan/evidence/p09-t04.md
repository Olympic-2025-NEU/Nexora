# P09-T04 — Inbound trust, inbox và dedupe

Client credentials token của realm nhận được xác thực lại ở service (JWKS, issuer, audience, expiry). `client_id`/`azp` và `federation:write` phải khớp active partner connection. Khi ghi inbox, service kiểm lại binding và trạng thái partner trong cùng transaction; `issuerInstanceId` trong body phải bằng instance ID của partner, `recipientInstanceId` bằng instance local. D05 chốt signed OIDC M2M, không yêu cầu body signature riêng.

`federation.inbox_message` giữ payload v1 đã validate, JCS SHA-256 và unique issuer+message / issuer+event+type. `federation.partner_ack` lưu ACK 202 cùng transaction. PostgreSQL advisory locks tuần tự hóa cả hai khóa replay khi nhiều request đồng thời. Replay cùng hash trả ACK đã lưu; đổi payload cùng message ID hoặc dùng message ID mới cho cùng event trả 409 và audit deny có mã, không log token/body. Không tạo stock movement hay business receipt. T05 trả `pending_dependency` khi lot/parent chưa được map; ACK replay vẫn giữ nguyên body ban đầu.

Mã lỗi API: `WRONG_ISSUER`/`WRONG_RECIPIENT`/`PARTNER_INACTIVE_OR_UNBOUND` 403; `MESSAGE_ID_REUSED`/`EVENT_ID_REUSED` 409; `PAYLOAD_TOO_LARGE` 413; `UNSUPPORTED_MEDIA_TYPE` 415; JSON/schema/policy sai 422. Các lỗi này có `retryable:false`; DB/auth service unavailable là 503 với `retryable:true`. Theo T02, lệch đồng hồ hơn 5 phút là cảnh báo, không từ chối payload hợp lệ; unknown lot/dependency được phân loại pending ở T05. ACK giữ chính xác bốn trường mà T03 outbound worker yêu cầu.

Kiểm chứng: `npm run typecheck`, `npm run test:identity`, `npm run test:platform:federation` (PostgreSQL disposable, migration đầy đủ). Integration kiểm tra forged issuer, wrong recipient, policy/version, payload tamper, same hash replay, event ID mới message ID, disabled/suspended partner, 12 request đồng thời cho một message và stock movement bằng 0. M2M qua gateway HTTPS thật đã được kiểm chứng trên ba DB/realm riêng trong [local smoke evidence](p09-local-m2m-smoke.md); G09 vẫn cần hành trình nghiệp vụ hoàn chỉnh.
