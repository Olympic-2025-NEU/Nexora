## Test setup

Host Docker 29.8.2 had no Compose plugin (`docker compose`: `unknown shorthand flag: 'f' in -f`). To run Compose v5.7.1, commands below use `docker:29-cli` with host Docker socket and checkout mounted at the same absolute path. The Docker CLI container needs `--security-opt label=disable` to access the socket on this SELinux host. The fresh run used `INSTANCE_ID=t03`, project `nexora-t03-fresh`, and newly created volume `nexora-t03-pg`. Only `CHANGE_ME_*` example credentials were used; no credential or dump was committed. The CLI image is a test tool, not a stack image.

```sh
npm ci
docker run --rm --security-opt label=disable -e DOCKER_HOST=unix:///var/run/docker.sock \
  -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD:$PWD" -w "$PWD" docker:29-cli \
  sh -c 'for i in a b c; do docker compose -f deploy/compose.yml --env-file deploy/instances/$i.env.example -p nexora-$i config -q || exit; done'
DATABASE_URL='postgresql://placeholder:CHANGE_ME@localhost:5432/placeholder' npx prisma validate
```

Results: `npm ci` exit 0; Compose A/B/C `config -q` exit 0; Prisma schema valid. The first test build exposed a non-root Prisma engine write error; migrator image now gives `node` ownership of installed dependencies. An obsolete, empty on-disk spike migration directory initially caused `P3015`; removing it from the build context resolved that. The first successful fresh-volume run below used the final migration, including `BEGIN`/`COMMIT`.

## Baseline backup and restore

```sh
docker exec nexora-t03-fresh-postgres-1 psql -U nexora_admin_a -d postgres -v ON_ERROR_STOP=1 -c 'CREATE DATABASE nexora_restore OWNER migrator;'
docker exec nexora-t03-fresh-postgres-1 pg_dump -Fc -U nexora_admin_a -d nexora | \
  docker exec -i nexora-t03-fresh-postgres-1 pg_restore -U migrator --no-owner -d nexora_restore --exit-on-error
docker exec nexora-t03-fresh-postgres-1 psql -U nexora_admin_a -d nexora_restore -Atc \
  "SELECT count(*) FROM public._prisma_migrations WHERE finished_at IS NOT NULL; SELECT count(*) FROM platform.audit_log WHERE request_id='p01-t03'; SELECT count(*) FROM pg_tables WHERE schemaname='platform' AND tablename IN ('audit_log','attachment','core_record');"
```

```sh
docker exec nexora-t03-fresh-postgres-1 psql -U nexora_admin_a -d postgres -v ON_ERROR_STOP=1 -c 'CREATE DATABASE keycloak_restore OWNER keycloak_a;'
docker exec nexora-t03-fresh-postgres-1 pg_dump -Fc -U nexora_admin_a -d keycloak | \
  docker exec -i nexora-t03-fresh-postgres-1 pg_restore -U nexora_admin_a --no-owner -d keycloak_restore --exit-on-error
docker exec nexora-t03-fresh-postgres-1 psql -U nexora_admin_a -d postgres -v ON_ERROR_STOP=1 -c 'CREATE DATABASE flowable_restore OWNER flowable_a;'
docker exec nexora-t03-fresh-postgres-1 pg_dump -Fc -U nexora_admin_a -d flowable | \
  docker exec -i nexora-t03-fresh-postgres-1 pg_restore -U nexora_admin_a --no-owner -d flowable_restore --exit-on-error
docker exec nexora-t03-fresh-postgres-1 psql -U nexora_admin_a -d postgres -Atc \
  "SELECT datname,pg_get_userbyid(datdba) FROM pg_database WHERE datname IN ('keycloak_restore','flowable_restore') ORDER BY datname;"
```

Results: app `CREATE DATABASE`; `pg_dump | pg_restore` exit 0; restored migration rows **1**, test audit rows **1**, platform tables **3**. Keycloak and Flowable restore commands exited 0; owner query returned `flowable_restore|flowable_a` and `keycloak_restore|keycloak_a`. These databases had no Keycloak/Flowable application rows at baseline. Dumps streamed between containers; no backup artifact written to checkout. Full application/object-store disaster recovery belongs to later tasks.
