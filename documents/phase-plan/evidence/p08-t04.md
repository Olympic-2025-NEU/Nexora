# P08-T04 — Forward trace and impact evidence

Date: 2026-11-24. Task branch: `phase08/p08-t04-forward-impact`.

## Implementation

- `GET /api/v1/lots/{id}/trace/forward` follows stored links in the source-to-downstream direction with depth 1–10, a visited set, a 2000-node cap, recorded-at snapshot cursor and pages. It reports source IDs, issuer-qualified origins, occurred/recorded times, verification state and explicit gaps. The authenticated route requires `trace:read` and disables caching.
- The impact list reads confirmed document lines for issue, transfer, receiving and sale events. Each row identifies its source document/line, quantity and unit. Receiving exposes sent and actual quantities separately. Transfer exposes the destination partner issuer and `unknown/downstream_unreported` until a verified summary arrives; P08 does not imply downstream receipt. Issue, transfer and sale can describe the same goods, so the UI does not sum them into a fictitious total.
- The forward and backward readers now filter trace events and links to the actor's warehouse scope. The impact query excludes sale buyer references and private document fields. `/trace` displays the local as-of time, projection lag, impact rows and gaps.

## Verification

OpenAPI is generated and validates with the forward graph/impact shape. CI is checked after pushing the task branch.
