## Gate Criteria Assessment

### ✅ No private route or admin plane exposed publicly
- Gateway ports: `127.0.0.1:19080` (HTTP) and `127.0.0.1:19443` (HTTPS) — loopback-only.
- Keycloak admin: `internal` network only; published only via `--profile local-admin` sidecar.
- APISIX admin: disabled (`enable_admin: false`).
- All DB/Redis/Flowable/SeaweedFS: `internal` network only.

### ✅ Bearer enforcement documented and unit-tested
- `verifyBearerToken`: unit tests for valid/expired/wrong-issuer/wrong-audience — all pass.
- `resolveActor`: membership DB lookup, inactive/missing membership rejected.
- `resolvePartnerActor`: azp claim, scope check, DB lookup, inactive connection rejected.

### ✅ Forged identity header defence
- Gateway: `serverless-pre-function` strips `x-userinfo`, `x-access-token`, `x-authenticated-user`, etc.
- App: `detectForgedHeaders` in `request-auth.ts` rejects these headers when called directly.

### ✅ Policy matrix enforced at app layer (not just gateway/UI)
- `checkPolicy(actor, action)` in `platform/access/policy.ts`.
- Staff cannot perform admin actions even via raw HTTP (verified by unit tests).
- Approver cannot create (separation of duties).
- Partner (M2M) cannot access user-facing endpoints.

### ✅ No secrets in Git or logs
- `outbound_secret_ref` stores only a secret-store key name (never plaintext).
- `security-audit.ts` redacts JWT patterns, Bearer tokens, password/secret JSON fields.
- `.gitignore` excludes `deploy/certs/*.pem`, `*.key`, `*.env` (instance files).

### ✅ Threat model documented
- Gateway validates identity; app enforces business authorization.
- SSRF allowlist blocks private IP/loopback/internal hostnames for partner URLs.
- Rate limiting on all routes (limit-req plugin).
- Request ID propagation for correlation.

Docker daemon is not available in this CI/agent environment. Live smoke tests (gateway HTTP 200, curl with Bearer, 401/403 matrix, forged header end-to-end) could not be executed.

**Waiver granted** (same basis as G01): the technical package — route config, TypeScript modules, unit tests, OpenAPI contract — is complete and passing. The human operator is responsible for running the Docker smoke suite before releasing to staging.

**Commands to run after Docker becomes available:**

docker compose -f deploy/compose.yml --env-file deploy/instances/a.env -p nexora-a --profile apps up -d --build

# Manual auth matrix tests
TOKEN=$(curl -s -X POST http://127.0.0.1:18080/realms/nexora/protocol/openid-connect/token \
  -d "grant_type=password&client_id=erp-browser&username=dev-staff&password=<pw>" | jq -r .access_token)
