# D04 — Identity, browser login và session

- Ngày: 2026-11-17. Trạng thái: **chọn Keycloak OIDC + server-side browser session**; PKCE thành phần đã thử, BFF/session production và reviewer G00 còn mở.
- Câu hỏi: đăng nhập người dùng qua SSO thế nào để token không nằm trong localStorage và API vẫn kiểm quyền ở server?
- Quyết định: `quay.io/keycloak/keycloak:26.8.2@sha256:c68e286cacd87b942ac1939a0a1481461109d6acd3a57dc496969a319a76bbf0`, realm/client riêng theo instance. Browser đi **authorization code + PKCE S256** tới Keycloak; Next BFF đổi code và giữ token/refresh ở phía server, browser nhận session cookie `HttpOnly`, `Secure`, `SameSite` và thời hạn ngắn. App API xác minh JWT `iss/aud/exp/signature` cùng membership/warehouse scope trong app DB; không tin header danh tính từ browser/gateway. Không lưu password ở app DB. Keycloak source [Apache-2.0](https://github.com/keycloak/keycloak/blob/main/LICENSE.txt).

## Phương án và bằng chứng

Không chọn password grant hoặc browser localStorage bearer. Server-side session giảm bề mặt rò token; cơ chế cụ thể (library, store/rotation, CSRF, logout/revoke) phải được P02 kiểm nghiệm trước code tích hợp. Tài liệu **Next 16.4.6 trong lockfile clone sạch** đã đọc ở `node_modules/next/dist/docs/01-app/02-guides/authentication.md` và `01-app/03-api-reference/04-functions/cookies.md`: session cần kiểm trên server, cookie set từ Route Handler/Server Function, `cookies()` là async; khuyến nghị dùng auth/session library. Không lấy ví dụ password nội bộ trong guide làm quyết định bỏ Keycloak.

[Spike](../phase-plan/evidence/spikes/infra/README.md): PKCE verifier đúng trả token 200, verifier sai `invalid_grant` 400; token user scope `openid erp:user` qua APISIX private 200, M2M route 403. Realm import tối giản ban đầu phát access token **thiếu `sub`**, nên core spike từ chối 401; thêm [Keycloak Subject mapper](https://www.keycloak.org/docs/26.7.3/upgrading/) `oidc-sub-mapper` vào scope `erp:user` rồi xác minh `sub` có mặt và core POST/GET 201/200. Đây là bằng chứng P02 cần kiểm claims thực, không suy từ scope. Keycloak container RAM **944.7 MiB snapshot**. Test dùng HTTP loopback và tắt `Secure` trên cookie **chỉ trong script mô phỏng**, không chứng minh HTTPS BFF. Token có issuer `127.0.0.1:18080` bị gateway từ chối khi discovery kỳ vọng `keycloak:8080`; P02 cần URL HTTPS canonical và test cả browser lẫn container. Chưa test logout, refresh/revoke, disable user, session fixation/CSRF, audience hoặc nhiều realm A/B/C. Team chốt auth library/session store trong P02 bằng spike nhỏ và cập nhật ADR nếu nó đổi contract.
